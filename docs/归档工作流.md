# 闲置话题归档

默认关闭。归档由 Codex 定时任务唤起，Stop Hook 只负责标题维护。默认保留最近 14 天的对话；闲置 14 天且明确完成，或闲置 30 天且没有明确待办，才列为候选。有待办或无法判断时保留。

## 交互与状态

- 呈现：首次在管理话题展示候选标题、闲置天数和原因；实际归档使用宿主工具。
- 状态：插件数据目录下的 `archive/` 保存开关、保护名单、内容指纹、简短评估和归档记录，不保存完整对话。宿主才是实际归档状态的来源。
- 动作：Python 先过滤；独立 Luna 只评估尚未判断的候选；主 Agent 不重新推理所有历史对话，不继续被整理话题的工作。
- 反馈：没有候选时不重复展示；实际归档或失败时给出简短结果和恢复方式。
- 恢复：通过宿主 `set_thread_archived(archived=false)` 恢复。插件已记录的归档终态仍受保护，避免刚恢复又被自动归档；用户明确要求时才执行 `release`。
- 降级：缺少宿主归档工具或新鲜保护名单时停止写入，保留预览。电脑需开机且桌面 App 运行；不承诺关机时执行。

## 首次预览

下文 `<归档入口>` 是 Skill 中 `scripts/archive.py` 的绝对路径。Windows 使用 `py -3` 替代 `python3`。

1. 调用宿主 `list_threads(limit=50)`。它始终返回完整置顶列表；将返回的 JSON 对象通过 stdin 交给 `python3 <归档入口> guards --current-id <管理话题ID>`。不得凭印象编造名单。读取失败、不完整或保护名单超过 5 分钟时停止。
2. 执行 `python3 <归档入口> scan`：只做确定性筛选，无模型调用。`scan --live --limit 10` 才允许最多 10 个新候选调用独立 Luna；此前用户已授权归档评估时可直接使用。
3. 把返回候选的标题、天数和原因展示给用户。预览不会归档，但保存评估缓存，后续正式执行无需重新付费判断同一份内容。
4. 用户认可预览后执行 `enable`。设置 Codex 官方定时任务；优先依附当前管理话题，默认每天本地时间 10 点。先检查既有自动任务，避免重复创建；不要用系统 cron 或私有调度配置绕过官方管理工具。

## 每次定时运行

1. 先运行 `status`；归档开关关闭时直接结束，不扫描也不调用评估模型。
2. 获取新鲜宿主 `list_threads(limit=50)`，执行 `guards`。保护置顶、运行/等待输入、当前管理话题、用户放进自定义分区的单独话题和活动自动任务的作用域。程序也保护显式保留的话题、已锁定标题及子 Agent 任务；无法判断活动自动任务作用域时停止。
3. 执行 `scan --scheduled --live --limit 10`。定时模式在开关关闭时直接结束，不能用普通预览模式绕过暂停。不要把扫描列表全部贴入主模型上下文；程序只返回计数和归档候选。没有候选直接结束。
4. 对每个候选，**紧接归档前**重新获取宿主列表并保存 `guards`，执行 `check <话题ID>`。只有返回 `ready_to_archive` 才调用宿主 `set_thread_archived(threadId=<话题ID>, hostId="local", archived=true)`；其余状态跳过。不得从旧预览直接归档。
5. 宿主成功后执行 `record <话题ID>`，它通过官方归档列表验证后记录终态。若宿主超时或结果不确定，先执行 `record` 核实；未确认则结束本次，不盲目重试归档。
6. 仅报告实际归档或异常。不要在定时任务中执行 `release`、清空缓存、恢复归档话题、读取它们的历史，或自动创建新的整理任务。

宿主归档与前置检查之间没有已验证的原子条件写入，因此保留很短的竞态窗口。检查发现新对话、运行状态或保护变化时会跳过；不能宣称完全消除宿主跨进程竞态。

## 防止重复消耗

- 扫描仅使用官方未归档列表，归档内容不进入模型；命名 Hook 也先检查归档状态。
- 内容指纹不包含标题和话题元数据更新时间。自动改名不会让闲置时钟归零，也不会触发再次归档评估。
- 相同内容版本只尝试一次模型；保留、不确定、异常或调用中断都缓存。达到 30 天门槛时复用原分类，程序自行判断，不再次调用模型。
- 归档使用原始目标与最近 5 个轮次中完整的用户消息、最终回答，不复用命名的短摘要。完整上下文超过 12,000 字符或加载不完整时保留话题，不截断中间或末尾的待办后强行归档。更早的未完成事项仍依赖原始目标与近期进展，有限上下文不能证明整个历史中没有待办。
- 旧版截断摘要产生的评估缓存不再放行自动归档，也不自动重新收费评估；需要重新判断时由用户明确要求 `release`。已记录的归档终态保持不变。
- 每个候选与真实模型启动前复核暂停状态；等待配额后也重新检查。暂停会停止后续调用并丢弃本次候选，已经发出的请求不能追回费用。命名的重名和格式重试同样在每次真实调用前检查归档、暂停与标题锁定状态。
- 有新对话后重新计算闲置时间，超过门槛时才重新评估。显式 `release` 可清除缓存重新判断。
- 归档终态永久保留；每轮扫描使用进程锁，防止两个整理进程重复调用模型。
- 定时管理 Agent 本身仍有唤起开销；这里保证的是已归档及未变化话题不重复调用评估模型，并非整个定时任务零 Token。

## 控制命令

`enable` / `pause` 独立于标题命名开关。暂停定时归档时，除程序 `pause` 外，也通过官方自动任务工具暂停对应计划，避免继续唤起管理 Agent。`protect <话题ID>` 永久保留；`release <话题ID>` 解除本插件的归档保护与评估缓存，不恢复原话题，也不启动对话。`status` 查看设置；`record` 只能在宿主已归档后记录成功。

当前活动时间需要兼容 App Server 返回真实轮次时间。旧话题缺失该数据时保守保留，不使用文件修改时间或标题更新时间代替。

参考：[官方定时任务](https://learn.chatgpt.com/docs/automations?surface=app)、[官方 App Server](https://learn.chatgpt.com/docs/app-server)。
