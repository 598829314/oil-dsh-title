## 可选归档验收（2026-09-14）

### Review 边界修复

- 归档改用近期完整消息，覆盖回答中段、末尾及长用户请求中的待办；超过上下文预算时保留，不调用模型。旧摘要缓存不能继续放行归档，也不自动重新收费评估。

## 尚未闭合的桌面显示问题

在当前 macOS 桌面版本中，独立 App Server 的 thread/name/set 可以更新持久标题，但置顶列表可能继续使用旧缓存。通过主 Agent 调用宿主 set_thread_title 后，列表能显示新标题。

这两个结果不能混为一谈：后台元数据改名成功，不等于宿主所有位置立刻刷新。doctor 的 desktop_display 返回 not_verified；renamed 的 verification 为 metadata_only。

当前没有验证出可供第三方后台 Hook 稳定使用的桌面刷新通道。不会为了绕过这个限制去改写桌面私有状态文件、恢复原任务、自动插入用户消息或接入未经支持的私有协议。

因此，宣称“所有任务自动更新且桌面立即一致”的发布条件尚未满足。本次以预览版公开并保留这项限制；完整自动体验仍需要可验证的宿主刷新接口或修复。

## 可复现检查

1. 记录某个置顶任务的标题与轮次数量。
2. 在插件命令行执行 rename <任务ID> --apply。
3. 读回标题元数据，确认新名称已保存。
4. 使用宿主 list_threads 检查置顶任务名称。
5. 如果仍是旧名，使用宿主 set_thread_title 设置步骤 3 的同一个名称，再次检查。
6. 对照原任务记录，确认测试只写标题元数据。

这项检查必须与普通非置顶任务分别执行。不要把 ready、命令成功退出或模型输出候选标题当作桌面验收通过。
